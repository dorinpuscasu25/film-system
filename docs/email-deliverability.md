# Email deliverability for filmoteca.md

Checked on 2026-08-04.

## Application configuration

- `MAIL_FROM_ADDRESS` must use the same authenticated domain as the SMTP provider. The recommended sender is `no-reply@filmoteca.md`.
- `MAIL_FROM_NAME` should be `FILMOTECA.md`.
- `MAIL_EHLO_DOMAIN` should be `filmoteca.md`.
- `APP_URL` must be the public HTTPS API URL so confirmation links do not point to localhost.
- `CLIENT_FRONTEND_URL` must be the public HTTPS storefront URL.

The previous local configuration used Mailgun SMTP with a `From` address on `boomnailshop.com`. That breaks domain alignment and is a likely spam signal. The repository defaults and the local sender were changed to `no-reply@filmoteca.md`.

## DNS state found during the check

- SPF: `v=spf1 a mx ip4:93.113.114.104 ~all`
- DMARC: `v=DMARC1; p=none`
- No DKIM record was found for the common selectors checked (`smtp`, `email`, `k1`, `k2`, `mailo`, `mg`, `pic`). The actual selector must be copied from the active email provider.

The current SPF record does not authorize Mailgun. Before production delivery, choose the actual sending provider and copy its SPF and DKIM values exactly from its dashboard. Keep a single SPF TXT record and merge all authorized senders into it.

After SPF and DKIM both pass and align with `From: ...@filmoteca.md`, move DMARC gradually from monitoring to enforcement:

1. Start with `p=none` and a reporting address.
2. Review aggregate reports and fix every legitimate sender.
3. Move to `p=quarantine`, initially with a limited percentage.
4. Move to `p=reject` after all legitimate traffic passes.

## Verification after DNS changes

1. Clear Laravel configuration cache: `php artisan config:clear`.
2. Send a real registration email to the temporary address generated by Mail-Tester.
3. Confirm that SPF, DKIM, and DMARC all show `PASS` and that the visible `From` domain is `filmoteca.md`.
4. Test the same email in Gmail, Outlook, and Apple Mail on narrow and desktop layouts.
5. Verify the confirmation button, six-digit code, expiration, resend behavior, expired code, and one-time link reuse.

DNS changes and provider-domain verification are external deployment actions; application code cannot publish those records.
